SECTION 2: INCIDENT RESPONSE

2.1 Severity Classification
P1 (full outage): 15-min response | P2 (major degradation): 30-min response
P3 (minor): 2-hour response | P4 (no impact): next sprint

2.2 Initial Response
1. Acknowledge PagerDuty alert within 5 minutes
2. Create incident ticket with correct severity level
3. Open Slack incident channel (#incident-YYYY-MMDD-NNN)
4. Notify stakeholders per the communication matrix

2.3 Diagnosis
Review monitoring dashboard → check deployment history (last 2 hours) →
examine error logs in Kibana → verify database and service health endpoints

---
SECTION 3: ACCOUNT PROVISIONING

Submit an Access Request form approved by the department manager and IT
Security. Provisioning SLA: 2 business days.

---
SECTION 4: VPN ACCESS

Requires: active employee account + MFA enabled + MDM-registered device.
Connect via GlobalProtect client only. Contact IT Helpdesk for setup.

---
SECTION 5: DEPLOYMENT PROCEDURE

All production deployments require:
1. Approved Change Request (CR) ticket from the Release Manager
2. Deployment window: weekdays 14:00–16:00 KST (no Fridays)
3. Documented rollback plan in the CR ticket
4. Post-deployment smoke test within 30 minutes

---
SECTION 6: SERVER INSPECTION CHECKLIST

| Check Item         | Alert Threshold    | Required Action            |
|--------------------|--------------------|-----------------------------|
| CPU utilization    | >80%               | Scale horizontally or tune |
| Disk usage         | >75%               | Expand volume or clean logs|
| Security patches   | Overdue >14 days   | Apply immediately           |
| Log retention      | <90-day minimum    | Review retention config    |
| Certificate expiry | <30 days remaining | Renew via PKI team          |

---
SECTION 7: INFRASTRUCTURE CHANGE MANAGEMENT

All changes follow the Change Advisory Board (CAB) process:
- Standard changes: pre-approved, log only
- Normal changes: CAB review, 5-business-day lead time
- Emergency changes: immediate CAB chair approval required
